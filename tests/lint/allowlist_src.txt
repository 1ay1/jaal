# Files in src/ allowed raw concurrency primitives, and which ones.
# See tests/lint/banlist.cmake.

# The POSIX signal handler may only touch lock-free atomics (per
# [support.signal]); the loop-side install/uninstall bookkeeping is under a
# mutex that the handler never takes.
platform/posix/signals.cpp: mutex atomic

# Same shape on Windows: the console control handler runs on a thread
# Windows creates and touches only atomics; install/uninstall use a mutex.
# std::thread appears only as this_thread::yield in the teardown wait.
platform/windows/console_signals.cpp: mutex atomic

# The wait_reactor keeps ONE process-wide, refcounted timer-resolution
# request (timeBeginPeriod/timeEndPeriod): a lock-free counter raised by the
# first live reactor and lowered by the last. It's an OS-resource refcount
# across reactor lifetimes, not app data, so an atomic is the right tool
# rather than a message loop.
platform/windows/wait_reactor.cpp: atomic
